# T10 — Wire dynamic sizing + third slot into the trader (F3, part 3 of 3) · claude

## Goal
With `trader.dynamic_size_enabled = true`: each entry is sized by `fork::balance::dynamic_trade_size`
from the cached SOL balance; the slot limit is `fork::balance::slot_cap`; the global position
semaphore is sized for the third slot at startup. Off ⇒ upstream behaviour, byte for byte.

## Inputs (read only, no new RPC, nothing under src/wallets or src/chains/solana/swaps edited)
- Balance: `crate::wallet::live_wallet_snapshot()` (src/wallets/balance_monitor/worth.rs, public,
  lock-free ArcSwap; refreshed every `wallet.snapshot_interval_secs` = 15 s and after each swap).
  `native_balance` is used only if `snapshot_time` is at most 300 s old (and not more than 60 s in
  the future); otherwise the balance is unknown (`None`).
- SOL/USD: `crate::apis::native_price::known_native_price()` (`None` when not fresh).

## Files to touch (3; differs from docs/TASKS.md)
1. `src/trader/config.rs`: pure helpers + accessor bodies + inline tests.
2. `src/trader/safety/limits.rs`: live entry check fails (Err) when dynamic size cannot be computed.
3. `src/positions/worker.rs`: semaphore init/reconcile use `semaphore_capacity`.
The plan named `src/positions/state.rs` and `tests/trading.rs`. The semaphore is initialised in
worker.rs, not state.rs, so state.rs is unchanged. Tests are inline because injecting a live wallet
snapshot from tests/ would need a src/wallets change. tests/trading.rs is the mainnet harness.

## Changes
### src/trader/config.rs (all `// FORK: F3`)
- `fresh_balance(balance, snapshot_time, now) -> Option<f64>`: the age rule above.
- `cached_sol_balance() -> Option<f64>`: live snapshot → `fresh_balance`.
- `trade_size_for(&TraderConfig, balance: Option<f64>) -> anyhow::Result<f64>`:
  off → `Ok(trade_size_sol)`; on → `dynamic_trade_size(balance, cfg)`.
- `max_open_positions_for(&TraderConfig, balance, sol_usd) -> usize`: off → `max_open_positions`;
  on → `slot_cap(..)`.
- `semaphore_capacity(&TraderConfig) -> usize`: off → `max_open_positions`;
  on → `max(max_open_positions, third_slot_max_positions)`.
- `dynamic_trade_size_now() -> Option<anyhow::Result<f64>>`: `None` when off, else the live size.
- `get_trade_size_native()`: off → unchanged. On → live dynamic size; on Err falls back to
  `trade_size_sol` (debug logged). Live entries never reach this fallback in the normal path,
  because limits.rs refuses them first. The fallback serves UI readers, the manual DCA default and
  paper mode.
- `get_max_open_positions()`: off → unchanged; on → `max_open_positions_for(live balance, price)`.
- `get_semaphore_capacity()`: live config → `semaphore_capacity`.
Balance/price are read outside the `with_config` closure (no nested locks).

### src/trader/safety/limits.rs
`check_position_limits()`: if `dynamic_trade_size_now()` is `Some(Err(e))` → return
`Err(TraderError)` (admission maps it to `EntryBlock::CheckFailed`). Otherwise upstream.
`position_capacity()` is unchanged in shape and uses `get_max_open_positions()` as before.

### src/positions/worker.rs
`let max_open_positions = crate::trader::config::get_semaphore_capacity();` for both init and
reconcile (reconcile computes consumed permits as `max_open - available`, so both must match).

## Known limits (report to owner, not fixed here)
- Soft cap race: with the semaphore at 3 and the cap at 2 (below $40), two entries that pass the
  capacity check at the same moment can both get a permit, so 3 positions can open below $40.
  The limit is a hard cap of 3. Upstream has the same race after max_open_positions is lowered live.
- Semaphore is sized at startup: turning `dynamic_size_enabled` on live needs one restart
  before a third slot can open (sizing and the 2-slot cap apply without a restart).
- Paper mode reads the live wallet balance for size and slots when enabled.

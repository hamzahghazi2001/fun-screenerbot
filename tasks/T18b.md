# T18b — OHLCV passed-first: order, priority, skip, 5m only (F-OHLCV, part 2 of 2) · flash-high

## Problem
With `ohlcv.passed_first` (T18) the OHLCV monitor should spend its GeckoTerminal budget on the
tokens the entry strategy can buy. Today (`src/ohlcvs/monitor.rs`):
- `monitor_loop` walks `active_tokens.keys()` (~line 1079-1082), a `HashMap`, so the order is arbitrary.
- Filter-passed tokens are added at `Priority::Low` (~line 2488-2493). Low scales the native 5m refresh
  interval by 15 (`native_refresh_interval_secs`, ~line 412), so their 5m candles refresh every 75 min.
- Every monitored token is fetched, passed or not.
- Every due aggregated timeframe (5m, 15m, 1h, 4h, 12h, 1d) is fetched natively; the strategy reads 5m.

## Behaviour when `passed_first = true`
- Held = mints of the live and paper books for this monitor's chain (the same set the slot sync
  already builds at ~line 2374-2387). Passed = `crate::tokens::get_passed_tokens(chain)`.
- Fetch order each cycle: held mints first, then passed (not held) mints, each group sorted by mint
  string. Every other mint is skipped: no candle fetch in `monitor_loop` and none in `gap_fill_loop`.
- The slot sync adds no new mint that is neither held nor passed (filter `plan.add`).
- A passed token is fetched with priority `max(stored, High)`; this is computed per fetch and NOT
  persisted, so a token that stops passing falls back to its stored priority. At High the native 5m
  refresh interval is the base 300 s.
- A passed token that `get_recommended_action` would `Throttle` is fetched instead (`FetchNow`).
  `Pause` is kept.
- A passed token whose stored priority is not `Critical` refreshes only the 5m timeframe natively.
  The 1m fetch stays: it gates the native refresh (`fetch_succeeded`, ~line 1626) and the other
  timeframes keep being derived from 1m locally (`refresh_derived_timeframes_from_1m`), at no API cost.
  Held tokens (Critical) keep every timeframe.

## Behaviour when `passed_first = false`
Identical to upstream: same iteration order, same priorities, same timeframes, same tokens fetched,
and no extra held/passed lookups in `monitor_loop`, `process_token`, `fetch_token_data` or `gap_fill_loop`.

## 1. `src/fork/ohlcv_priority.rs` (pure, no I/O, no config reads)
Use `crate::ohlcvs::{Priority, Timeframe}` and `std::collections::HashSet`.

```rust
/// Mints to fetch this cycle. `enabled == false`: `mints` unchanged (same order, all kept).
/// `enabled == true`: mints in `held` (sorted), then mints in `passed` and not in `held`
/// (sorted); every other mint is dropped.
pub fn fetch_order(mints: Vec<String>, held: &HashSet<String>, passed: &HashSet<String>, enabled: bool) -> Vec<String>;

/// Whether `mint` may be candle-fetched at all. `enabled == false`: always true.
/// `enabled == true`: true only for a held or passed mint.
pub fn may_fetch(mint: &str, held: &HashSet<String>, passed: &HashSet<String>, enabled: bool) -> bool;

/// Priority a fetch uses: `stored.max(Priority::High)` when `enabled && passed`, else `stored`.
pub fn effective_priority(stored: Priority, passed: bool, enabled: bool) -> Priority;

/// Native aggregated timeframes to refresh: `Some(&[Timeframe::Minute5])` when
/// `enabled && passed && stored != Priority::Critical`, else `None` (= every timeframe, upstream).
pub fn native_timeframes(stored: Priority, passed: bool, enabled: bool) -> Option<&'static [Timeframe]>;
```

Unit tests in the same file (`#[cfg(test)] mod tests`), exactly these names:
- `ohlcv_passed_first_off_keeps_order_and_all_tokens`: off returns the input Vec unchanged, unpassed included.
- `ohlcv_fetch_order_held_then_passed`: on, input `["p2","x","h1","p1"]`, held `{h1}`, passed `{p1,p2,h1}` → `["h1","p1","p2"]`.
- `ohlcv_fetch_order_skips_unpassed_unheld`: on, a mint in neither set is absent; `may_fetch` false for it, true when off.
- `ohlcv_fetch_order_held_not_passed_kept`: on, a held mint that is not passed is kept, first.
- `ohlcv_passed_token_gets_high_priority`: on + passed: Low → High, Medium → High, High → High.
- `ohlcv_critical_stays_critical`: on + passed: Critical → Critical.
- `ohlcv_off_priority_unchanged`: off + passed: Low → Low; on + not passed: Low → Low.
- `ohlcv_passed_native_timeframes_only_5m`: on + passed + Low/High → `Some([Minute5])`.
- `ohlcv_held_and_off_fetch_all_timeframes`: on + passed + Critical → `None`; off → `None`; on + not passed → `None`.

## 3. `src/ohlcvs/monitor.rs` (wiring)
Read the flag with `with_config(|cfg| cfg.ohlcv.passed_first)` once per cycle / per call.

a. Extract the held-mints block in `sync_pool_service_tokens` (~line 2374-2387: the `match
   crate::positions::db::get_store_chain()` that builds `open_positions`) into a private
   `async fn held_mints(&self) -> std::collections::HashSet<String>` on the same impl, with the same
   body and logging, and call it there. No behaviour change.

b. `monitor_loop` (~line 1079-1082): when the flag is on, build `held` (a) and `passed`
   (`get_passed_tokens(self.db.chain())` into a HashSet) and replace `tokens` with
   `fetch_order(tokens, &held, &passed, true)`. Pass `passed.contains(&mint)` to `process_token`.
   When off, keep the current code path and pass `false`.

c. `process_token(&self, mint: &str)` → `process_token(&self, mint: &str, passed: bool)` (its only
   caller is `monitor_loop`). When `passed` is true and the flag is on, turn `Throttle(_)` into a
   fetch (`self.fetch_token_data(mint).await?`). `Pause` stays a skip.

d. `fetch_token_data` (~line 1356-1362, where `priority` is read from `active_tokens`): when the flag
   is on, compute `passed` with `get_passed_tokens(self.db.chain()).iter().any(|m| m == mint)` and use
   `effective_priority(stored, passed, true)` as `priority`; keep `stored` for (e). When off, no lookup.
   Do not change the signature of `fetch_token_data`.

e. `refresh_native_timeframes` (~line 3070) and `refresh_then_deepen` (~line 3112) each gain a
   parameter `timeframes: &[Timeframe]`; the `for timeframe in AGGREGATED_TIMEFRAMES` loop
   (~line 3135) iterates `timeframes` instead. The call at ~line 1627 passes
   `native_timeframes(stored, passed, flag).unwrap_or(&AGGREGATED_TIMEFRAMES)`. The existing test
   call at ~line 5449 passes `&AGGREGATED_TIMEFRAMES` (no other change to that test).

f. `gap_fill_loop` (~line 2193-2199): when the flag is on, drop from `tokens` every mint for which
   `may_fetch(&mint, &held, &passed, true)` is false, before the budget loop.

g. `sync_pool_service_tokens`, before the `for mint in &plan.add` loop (~line 2488): when the flag is
   on, skip any mint that is neither in `open_positions` nor in `passed`. Do not change
   `plan_monitor_slots` or any priority stored by `add_token`.

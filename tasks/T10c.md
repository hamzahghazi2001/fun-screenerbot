# T10c — Cap the permit check when dynamic sizing is off (F3 follow-up) · claude

## Problem (fresh-session review of T09/T10/T10b, its one should-fix)
`permit_within_slot_cap` (`src/trader/config.rs:131`) returns `true` whenever
`dynamic_size_enabled = false`. The global position semaphore is sized once at boot:
`max(max_open_positions, third_slot_max_positions)` = 3 when dynamic sizing was on at boot.
Boot with it on, switch it off at runtime: the semaphore still holds 3 permits and nothing caps them,
so manual and copy-trade opens (which pass only the semaphore) reach 3 positions with
`max_open_positions = 2`, and two automatic entries racing `check_position_limits` at 1 open can too.

## Fix
- `permit_within_slot_cap(in_use)`: when off, return `in_use <= get_max_open_positions()`
  (off → `max_open_positions`); on → unchanged.
- `permit_within_cap(trader, in_use, balance, sol_usd)` (the pure twin): when off, return
  `in_use <= trader.max_open_positions`, i.e. `in_use <= max_open_positions_for(..)` in both modes.

## Tests (inline in `src/trader/config.rs`)

  asserted the old behaviour): off, default cap 2: 2 allowed, 3 refused; `max_open_positions = 7`: 7 allowed, 8 refused.
- `permit_check_switched_off_at_runtime_caps_third_permit`: semaphore built on (`semaphore_capacity(&on()) == 3`),

  `a_slot_is_released_at_most_once_however_many_paths_run`; then the full suite.

## Behaviour change with the flag off (all stricter, never looser)
Off from boot, the semaphore holds `max_open_positions` permits and `in_use` never exceeds it, so the
check refuses nothing upstream allows, except:
- more positions open at boot than `max_open_positions` (boot overflow): upstream reopens as soon as
  one closes; now it waits until the count is back under the cap;
- `max_open_positions` lowered at runtime: upstream keeps the boot-time semaphore size; now the live value caps it.
